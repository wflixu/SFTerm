## 0.2.0：两个必须解决的问题

这两件事都不是「加个功能」，而是**数据放在哪、谁能读到、老数据怎么迁**。它们互相牵动：

- 都要求先把「本地持久层」从 localStorage 换出来（SQLite）；
- 都涉及敏感数据，安全边界要一次划清楚，避免后面再改协议；
- 都要处理已有数据，不能只考虑全新安装。

**0.2.0 检查清单**

- [x] TODO-1 密码存储：主机密码 / 私钥进系统钥匙串，旧数据启动时自动迁移
- [x] TODO-1 收尾：私钥口令、Keychain 条目回收、引用检查
- [x] 持久层：SQLite（hosts / keys 的 JSON state + command_history 表）
- [x] TODO-2 Snippets：片段 CRUD、最近命令落库、终端输入联想（视觉待定）
- [ ] 发布前人工验证：老主机能连、老密钥能用、片段能联想
- [ ] 补全准确性：OSC 133 命令边界替代回车启发式
- [x] 补全视觉：按参考图实现候选框（输入起点对齐、圆形图标、↵ 提示）

### TODO-1：密码的存储

**进展（0.2.0）**

- 已实现：`secret_set` / `secret_get` / `secret_delete` 三个命令接系统钥匙串（service `cn.wflixu.sfterm`），主机密码与密钥私钥文本在启动时从 localStorage 迁移进钥匙串，迁移成功后从 `hosts` / `keys` 里抹掉。
- 主机地址、公钥等元数据仍在 localStorage；SQLite 持久层未做。
- 私钥口令已支持：Keychain 条目里可保存口令（`key:<id>:passphrase`），连接时一并传给 Rust。
- 删除密钥会列出正在使用它的主机；删除主机 / 密钥时同步清理钥匙串条目，启动时也会清理与当前数据不一致的密码 / 口令。
- 私钥文件路径方式仍不支持口令（只有 Keychain 条目支持）。
- 主机编辑里「密钥」认证改为从 Keychain 条目下拉选择，连接时用 `userauth_pubkey_memory` 内存认证；Keychain 页改为卡片网格。
- 已知限制：开发版每次重编译签名会变，钥匙串 ACL 可能重新弹授权；从 dev 切到正式签名版时，旧条目可能因签名不同读不到，需要重新填一次密码。

**改之前的现状**

- 主机密码、私钥文本、口令全部以明文存在 WebView 的 localStorage（`hosts`、`keys` 两个键），Rust 侧不落盘。
- 连接时把明文密码从 JS 经 Tauri command 传给 Rust（`AuthMethod::Password` / `Key { passphrase }`）。
- Keychain 页只是一个条目管理器，主机表单只填「私钥**路径**」，`IHost.keyId` 字段没有接线 —— 密钥条目和实际连接完全无关。
- 打开一次 WebView devtools、或备份 `~/Library`，凭据就等于泄露。

**目标**

- 密码、私钥内容、口令进 macOS Keychain（`security-framework` 或 Tauri stronghold）；主机名、地址、端口、分组等非敏感元数据进 SQLite。
- 页面不长期持有明文：连接时由 Rust 侧取凭据，或经一次性句柄传递。
- 老数据自动迁移，迁移成功后从 localStorage 抹掉；失败可回滚。

**需要先定的问题**

1. **私钥怎么存**：整段私钥文本进 Keychain，还是只存文件路径、连接时读文件？现在两种做法混着，得选一种。
2. **Keychain 条目命名**：service / account 与主机 id 的对应关系；主机删除或 id 变化后如何回收，避免孤儿条目。
3. **开发版签名**：`pnpm tauri dev` 每次重编译签名会变，Keychain 的 ACL 可能反复弹窗甚至拒绝访问 —— 需要固定开发签名或明确的访问控制策略。
4. **Keychain 不可用时**：报错并要求重试，还是降级到只读？明文回退应该直接排除。
5. **口令字段**：passphrase 要不要一起进 Keychain，主机表单补上输入框（现在引擎支持、表单没有）。
6. **系统 Keychain vs stronghold**：前者跟 macOS 账户走、系统备份行为明确；后者是自带加密文件，跨机器复制更可控。需要选一个，并写进 ADR。

**验收**

- 迁移后 localStorage 中不存在密码 / 私钥文本。
- 重启、断网重连仍能登录，且 Keychain 里能看到对应条目。
- 老数据（包括没有 id 的历史主机）迁移不丢主机。
- 删除主机时同步清理对应 Keychain 条目。

### TODO-2：Snippets 与终端联想

**进展（0.2.0）**

- 命令执行记录落 SQLite（`command_history`），作为「最近命令」的数据源。
- Snippets 页：片段的增删改查（名称 / 命令 / 分组），最近命令可一键「存为片段」。
- 终端联想：输入 ≥2 个字符弹出候选；**已保存片段优先，未保存的历史排后面**；`↑/↓` 选择、`Tab` 整行替换、`Esc` 关闭；alternate buffer（vim / tmux）不弹。
- 不再有独立的 History 页面；侧栏恢复为 `Logs`，功能另议。

**待定 / 后续**

- 候选列表的视觉样式等设计图确认后再调。
- 补全边界仍是回车启发式，只有命令行、没有输出 / 退出码。
- 回显关闭的密码提示（如 `sudo`）仍会被当作命令记录，需要 OSC 133 或额外策略解决。

**验收**

- 输入 2 个字符出现候选；片段永远排在历史前面。
- `Tab` 用整条命令替换当前行；补全关闭时 `↑/↓` 仍然走 shell 自己的历史。
- 从 Snippets 页「最近命令」保存后，片段立刻出现在终端联想里。
